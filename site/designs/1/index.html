github.platform.sovereignweb.site

Your GitHub access, at a glance

See every repository you can reach, your role on each, and who else has access: people, teams, deploy keys, webhooks and rulesets. It only reads. An unofficial site, not made or endorsed by GitHub.

When you press the button, your token goes from this tab to api.github.com and nowhere else; this page names only that host in its security policy.

Your token stays with you

  • It is kept only in this tab's memory: reload or close the tab and it is gone. It is never stored, never logged and never sent anywhere but api.github.com, straight from your browser. This site has no server.
  • The page only reads: it makes GET requests and nothing else, so it cannot change your repositories even with a token that could.
  • Make a fine-grained token with read-only access: Metadata, Administration (to see people, keys and rulesets) and Webhooks, on the repositories you choose. Give it a short expiry. An organisation may need to approve it.

What comes next

  • Each repository now shows what stands out: public with you as admin, archived, a fork, no push for a year; and in its access view, a deploy key that can push, a webhook without HTTPS, no active ruleset.
  • Signing in with GitHub instead of pasting a token. GitHub's login step does not allow calls from a web page, so it needs one small exchange step off the page; that waits for the owner's word.
  • For the SovereignWebsite organisation, changes are proposed to SovereignWebsite__Factory, which runs it as code; this site never applies them.
